# 字钟开发调试手记 · 系列索引

> **统一主标题**：从一块灯板到一台中文字钟
> **格式**：`# 主标题` + `### NN｜本篇副标题` + 一段承上启下的过渡 + 导语

这套文章来自一个真实项目：基于官方开源项目 [Multilayout-ESP-Wordclock](https://github.com/ESPWortuhr/Multilayout-ESP-Wordclock) 5.0.0 做二次开发——

- **第一版是硬件**：11×10+4 的 LED 灯珠电路板、亚克力丝印板、隔光支撑板；
- **第二版是固件**：中文布局 `ZH10x11`。中文丝印留出大量空白格，于是把星期、天气、温度塞进最后几行；
- 塞进去之后，天气源、TLS/gzip、堆碎片、1℃ 精度、免 key 配置、中文界面……问题一个接一个，就有了这七篇文章。

每篇都按同一个结构写：**现象 → 排查 → 根因 → 解决 → 验证 → 复盘**。每篇中英文各一份（中文在前，`---` 之后是英文全文），可直接用于个人博客；公众号只取中文部分即可。

## 版式规范

**① 统一主标题，各自副标题。** 七篇共用一个主标题，读者从任何一篇点进来都知道自己在哪个系列里；编号与本篇题目放在副标题里。

```markdown
# 从一块灯板到一台中文字钟

### 04｜开机就 `wdt reset`：从静态初始化到堆碎片
```

**② 标题之后先过渡，再入题。** 每篇正文前固定一段承上启下的文字，格式统一为加粗引导词 + 一段话：

- 00 用 **开篇**（系列第一篇，说明为什么要先讲背景）；
- 01–06 用 **接上篇**（一句收上一结论，一句抛本篇问题）。

这段的作用是把连载接起来：公众号读者是零散进入的，没有它，每篇都像凭空开始；博客读者顺着读，它就是章节之间的台阶。

**③ 过渡之后才是导语。** 过渡讲"从哪来、到哪去"，导语（`>` 引用块）讲"这篇凭什么值得读"，两者不重复。

**④ 英文版同构**：`# English version` → `### NN · English subtitle` → `*Previously: ...*`。

## 建议发布顺序

- **按时间线**（推荐给博客连载）：00 → 01 → 02 → 03 → 04 → 05 → 06。00 是背景篇（硬件从哪来、中文布局为什么长这样），之后故障依次出现，读者跟着走一遍就是完整的排障路径。
- **按主题**（推荐给公众号单篇投放）：00 和 05 是"硬件/面板"上下篇，03 和 04 是"嵌入式内存"上下篇，02 和 06 是"数据源选型"上下篇，01 可以独立成篇。

如果只发一篇，选 **02** 或 **04**：前者有"握手成功≠服务可用"的反直觉结论，后者有"19 KB 空闲却 malloc 失败"的具体数字，传播性最好。

## 微信公众号

几个实际的限制，发布前处理一下：

1. **只发中文部分**。公众号编辑器对长英文段落不友好，双语混排会打断阅读。
2. **外链不可点**。文中的 URL（如 `http://<IP>:81/update`）保留为纯文本即可，不要做成超链接。
3. **代码块会换行**。公众号的代码样式在手机上宽度很窄，本文的代码片段都已控制在 70 字符内；如果某段仍然折行，建议截成图片。
4. **插图要先上传到素材库**，再把 `images/xxx.png` 换成微信的图片地址。
5. **开头三行决定留存**。过渡段与引用块就是为导语写的，直接放正文最前面；嫌长的话，只留过渡段的最后一句。
6. **标题用「主标题｜副标题」合成一行**（更符合公众号习惯）：
